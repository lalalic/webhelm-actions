# Full post and draft inventory reconciliation

A read-only Studio monitor is **not** a complete publication inventory. In the current Actions implementation it samples up to 30 visible rows, and neither TikTok nor YouTube monitor proves pagination reached the end. Any nonempty sample, absent `posts` array, stale observation, account mismatch, or uncertain list state blocks automated `post`. Caller-provided `coverage_complete:true` is **not** trusted. Never alter monitor output or override this gate merely to publish.

## Manual audit when current monitored inventory is incomplete

A separately authorized human operator on the intended Worknode must:

1. **Establish context.** Identify the actual signed-in TikTok handle or YouTube channel ID, the independently approved campaign/revision and video SHA-256, the exact publication account, visibility and unique attempt ID. The caller's `confirm_publish` flag is not an owner authorization. Verify the upstream business release proof and existing attempted-post ledger before proceeding.
2. **Exhaustively inspect published and hidden items.** In the platform's authenticated Studio, enumerate **all pages**, scrolling/paginating until a verifiable end-of-list. Include all public, private, friends/unlisted, scheduled and processing entries accessible to the owner, not just the latest 30, and record post IDs/URLs, creation dates, captions/titles, account identity, visibility and relevant screenshots. If any history page, filter or visibility bucket is inaccessible, record `HOLD`.
3. **Inspect drafts and incomplete submissions.** Check TikTok drafts and upload history; for YouTube inspect Studio videos, Shorts, drafts, private, scheduled and processing tabs. Check platform upload notifications and failed submissions. Do not infer an empty draft inventory from an empty published-post list. If draft evidence cannot be obtained, record `HOLD`.
4. **Reconcile all private attempt records.** Search **every** canonical private Run for prior attempts and receipts for this account, revision and video SHA-256, including `reserved_unverified`, `submitted_unverified`, timeouts and partial uploads. Match each attempt to an existing post, draft or documented absent state using exact recorded evidence. Do not just change `publication_attempt_id` to bypass an unresolved attempt.
5. **Save immutable audit evidence privately.** Under the *canonical* ignored campaign Run, record `inventory-review.json` with `platform`, `account_id`, `expected_account`, `video_sha256`, `creative_revision_id`, `publication_attempt_id`, `observed_at`, `reviewed_by`, `reviewed_source_urls`, `all_pages_exhausted`, `post_ids`, `draft_ids`, `prior_attempts_reconciled`, `evidence_files` plus SHA-256 of their bytes, and `decision` (`HOLD` or `CLEARED_FOR_MANUAL_UI`). Capture authenticated account identity, the first and final page/scroll position, observed post rows, drafts and relevant upload receipts. Require independent review of any unresolved ambiguity. Store private screenshots, full inventories and identifying evidence only in the ignored Run; never in this public Actions repository.
6. **Choose a permitted continuation.** If a documented complete review finds an existing matching item, reconcile its state and **do not upload**. If it proves no prior item/attempt exists and the business-side owner/rights/Safelist/link gates and attempt reservation are genuinely satisfied, the owner may **separately authorize a human to publish manually in the platform UI**. The present generic automated `post` Action remains blocked for nonempty inventories; a human audit does not magically make the monitor's 30 rows complete. To automate in the future, implement and test a genuine platform-owned, paginated all-post/all-draft inventory readback with end-of-list evidence, rather than accepting a caller's completeness flag.
7. **Close with observed outcomes.** A browser Post/Save click is only `submitted_unverified`; record actual post URL/ID and visibility separately. For a timeout or uncertain click, STOP, refresh account/drafts/inventory, reconcile the same attempt and request new explicit human authorization before any subsequent upload.

## Video staging across nodes

An upstream business gate may return a **Neo Master absolute** video path; it is **not** necessarily valid on Worknode. For any later authorized release, transfer the exact approved bytes to a **private Worknode local staging path**, calculate SHA-256 from that file on Worknode and compare with the approved release digest **before** even opening the upload workflow. Use that Worknode-local path as `video` and pass the signed digest as `video_sha256`. Generic Actions rehash the staged file immediately before native upload and before a CDP fallback. A mutable path can still be changed after a check; keep staged media immutable during the operation and reconcile any ambiguous upload. Neither a matching path name nor a caller boolean proves byte identity.

This is an operating procedure, **not authorization** to publish anything now. Live upload, public-account modification and profile-link changes require distinct explicit owner approval.
